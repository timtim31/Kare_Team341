
**Оговорка разработчика и условия использования**

Применять только в учебных целях. Данный код разработан в рамках практического моделирования политик безопасности кибериммунной системы «Корсет». Программный стек симуляции может содержать ошибки, автор не несёт никакой ответственности за любые последствия использования этого кода. 

**Системные требования**

Данный пример адаптирован и проверен на ОС macOS (поддерживаются архитектуры как на базе процессоров Apple Silicon M1/M2/M3/M4, так и на базе Intel). Для корректной установки и сборки зависимостей в системе должен быть установлен менеджер пакетов Homebrew. В отличие от Linux-систем, на macOS развертывание контейнеров Docker требует предварительного запуска графического приложения Docker Desktop.

**Используемое ПО**

Стандартный способ запуска демо-версии архитектурных компонентов предполагает наличие установленной среды Docker Desktop (версия движка Docker не ниже 25).

Для автоматизации типовых операций используется утилита make (требуется наличие установленного пакета Xcode Command Line Tools или установка через brew). При необходимости можно обойтись без неё, вручную выполняя соответствующие команды из файла Makefile в командной строке (Terminal.app).

Другое используемое ПО (установка на macOS описана в следующем разделе):

- python (версия не ниже 3.8)

- pipenv (для изоляции виртуальных окружений python)

- pytest (фреймворк тестирования для валидации политик безопасности)

Для работы с кодом примера рекомендуется использовать VS Code или PyCharm.
В случае использования VS Code следует установить расширения:

- REST client

- Docker

- Python


**Настройка окружения и запуск примера**

Подразумевается наличие развернутой по предоставленному образцу машины с установленным и настроенным ПО.  

Подготовка среды разработки, изоляция окружения и установка необходимых зависимостей (включая фреймворк тестирования):  

- make dev_install (Установка зависимостей)

- make all (Запуск контейнеров)

- make logs (логи)  

- make test (Запуск стандартного e2e тест проверки базовой функциональности взаимодействия узлов)

- make test_security (Запуск  15 негативных сценариев с использованием Pytest для проверки кибериммунных инвариантов)

- make clean (Завершение работы симулятора, остановка контейнеров и очистка временных файлов окружения)
